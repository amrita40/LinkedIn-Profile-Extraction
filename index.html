What it does

One call, one normalized schema — designed to stay stable even as LinkedIn's internal API changes underneath it.

01

Direct API calls

httpx requests straight to LinkedIn's Voyager endpoints. No browser automation anywhere in the deployed service.
02

Own schema, not a dump

Raw LinkedIn JSON is resolved and reshaped before it ever reaches a client — see the schema below.
03

Graceful gaps

Missing sections (no certifications, no about) return as empty, never as a 500. metadata.status tells you if a result is partial.
04

Cached & rate-limited

Repeat lookups are served from cache; both this API and the upstream session are protected from overuse.

Usage notice

!

This project uses direct, authenticated HTTP requests only — never a browser. The deployed service makes plain httpx calls to LinkedIn's own internal endpoints, replaying the session cookies from one authorized, human login. Nothing here scripts a login, solves a CAPTCHA, or drives a headless browser.

It authenticates as a specific LinkedIn account and can only see what that account can see. Reusing a session this way is against LinkedIn's User Agreement, and LinkedIn has pursued legal action against scraping tools before — that risk belongs to whoever's session is configured, not to a visitor of this page.

This page never touches LinkedIn directly. It only calls the API endpoint below, which is under your control.
